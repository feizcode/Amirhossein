# برنامهٔ پیاده‌سازی و ادامهٔ پروژه

این برنامه هم وضعیت ساخت موجود را ثبت می‌کند و هم ترتیب کار بعدی را پیشنهاد می‌دهد. مدت و تاریخ تحویل آینده تعهد نشده‌اند؛ نام مسئول قطعی هنوز ثبت نشده است.

## توالی ساخت نسخهٔ ۱

| مرحله | خروجی و وابستگی | شرط عبور | وضعیت شاهد |
|---|---|---|---|
| ۱. تعریف محصول | BRD → PRD → سفر/وایرفریم | دامنه، پیشرفت و نقش‌ها روشن | این مجموعه پس از پیاده‌سازی بازسازی شده؛ تأیید تاریخی طراحی اولیه موجود نیست |
| ۲. زبان بصری | برند → سیستم طراحی → نماهای دقیق | RTL، موبایل، حالت خالی و خطا تعریف | CSS/قالب موجود؛ آرتیفکت طراحی در این پوشه |
| ۳. پایهٔ داده | schema و catalog، سپس Calendar | ۶ درس، ۱۵ منبع و شروع خالی | موجود در کد و گزارش آزمون قبلی |
| ۴. منطق و API | فعالیت، تکلیف، extra، challenge، منبع و گزارش | قواعد REQ-03 تا REQ-10 برقرار | موجود در Learning/Application |
| ۵. حفاظت و بازیابی | نشست، CSRF، خصوصی‌سازی و Backup | ورود/خروج، منع مسیر خصوصی، restore | موجود؛ شواهد فنی قبلی ثبت شده |
| ۶. اتصال رابط | API واقعی و state سرور | مرورگر دوم دادهٔ یکسان ببیند؛ موبایل خوانا | گزارش پذیرش قبلی |
| ۷. ساخت و انتشار | assets → SQL اولیه → ZIP → هاست مستقل | نبود راز و دادهٔ تست؛ smoke و restore محیط واقعی | manifest و وضعیت انتشار موجود؛ بازتأیید زنده در این کار انجام نشده |

آرتیفکت‌های بازسازی‌شده مستندسازی وضعیت موجودند؛ وجود آن‌ها به معنی آن نیست که همه پیش از کدنویسی تأیید شده بودند.

## ترتیب پیشنهادی ادامه

۱. **عملیات قابل تداوم:** TASK-01 تمدید TLS، سپس TASK-02 اصلاح ناسازگاری راهنمای بازیابی. TLS به مالک زیرساخت و روش پشتیبانی هاست وابسته است؛ نتیجه باید در evidence ثبت شود.

۲. **تصمیم بازیابی:** TASK-03 تحمل از‌دست‌رفتن داده، نسخهٔ خارج از هاست و زمان بازیابی. ابتدا توافق عملیاتی و آزمون محیط جدا؛ سپس در صورت نیاز تغییر معماری بکاپ.

۳. **نگه‌داری مستندات:** TASK-04 نسخه‌گذاری و همراه‌کردن Artifacts با بستهٔ سورس. تغییر allowlist بسته باید از ورود راز یا فایل موقت جلوگیری کند.

۴. **اعتبار ارزش:** TASK-05 آزمایش ۱۴روزهٔ پیشنهادی. قبل از افزودن قابلیت بزرگ، فایده و اصطکاک ثبت بررسی شود.

۵. **بهبود تجربه:** TASK-06 دسترس‌پذیری و TASK-07 ویرایش چالش. تغییرات باید به نیازمندی، نمای طراحی و آزمون متصل شوند.

۶. **رشد مشروط:** TASK-08 کارایی و TASK-09 تعارض نوشتن فقط اگر حجم/رفتار استفاده نیاز را نشان داد. چند خانواده، حساب مستقل، AI و برنامه‌ریز هفتگی نیازمند تعریف محصول تازه‌اند و تعهد نسخهٔ فعلی نیستند.

## تعریف آماده‌بودن و پایان کار

یک تسک آماده است اگر مسئله، نیازمندی، مسئول پذیرفته‌شده، وابستگی و معیار پذیرش دارد. پایان کار یعنی خروجی بازبینی‌پذیر، تست متناسب، به‌روزرسانی تصمیم و سند، نبود راز در تحویل و ثبت نتیجه با تاریخ/محیط. «کد نوشته شد» یا «UI باز شد» به‌تنهایی پایان نیست.

برای انتشار: [runbook](release-runbook.md). برای فهرست دقیق کارها: [backlog](tasks/backlog.md). این برنامه مجوز اجرای خودکار تغییرات روی هاست یا نوشتن دادهٔ واقعی ایجاد نمی‌کند.
